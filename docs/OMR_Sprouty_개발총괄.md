## ★ 0. 최우선 원칙 — 모든 위치와 방향은 원본 이미지가 정한다 (v2.30, 사용자 확정)

> **편집 악보에 그리는 모든 기호의 위치·방향·모양은 절대적으로 원본 이미지를 기준으로 한다.**
> 계산(조판 규칙)으로 정하는 것은 **원본에 근거가 없을 때만** 쓰는 대비책이다.
> 이 원칙은 예외 없이 모든 기호에 적용하며, 새 기능을 만들 때도 먼저 '원본에서 이 기호의 자리를 어떻게 얻는가'를 정한다.

**원본 근거의 우선순위:** ① Audiveris가 인식한 기호의 원본 좌표·모양(.omr의 bounds·curve·median·relation) ② 원본 그림의 잉크를 직접 읽은 값(인식되지 않은 기호) ③ 둘 다 없을 때만 계산.

**계산으로 돌아가는 경우(그 기호만):** 사용자가 편집해 원본 모양이 더는 맞지 않을 때 — 음높이·길이·자리를 바꾼 음(`_orig`와 다름, `layout._pristine`), 새로 넣은 음. 편집하지 않은 나머지는 계속 원본을 따른다.

## ⏸ 보류(미적용) 과제 — 나중에 다시 결정할 것

### P-1. 화음에 가려진 빈 머리 누락 + '쉼표 생략'으로 정상 처리됨 ("교회" 9마디 오른손) — 2026-10-29 보류 → **v2.70 해결(C안)**
**현상:** 9마디 오른손 1박의 G♯4 2분음표(위 기둥)가 편집 악보에 없다. 원본은 G♯4(빈 머리, 위 기둥)와 F♯4(검정, 아래 기둥)가 2도로 붙은 두 성부. 위 성부 = G♯4 2분 + 점4분 + 16분 둘 = 4박, 아래 성부도 4박. 편집 악보의 위 성부는 2박뿐인데 마디가 '정상'(파란 음영 없음).

**Audiveris 인식 여부:** 1박 자리의 머리는 F♯4 검정 머리 하나뿐(0.789), 기둥도 아래로 뻗은 것 하나뿐. **G♯4 빈 머리와 위 기둥은 인식 결과에 아예 없다.** F♯4도 Audiveris가 음악(MusicXML)에서 뺀 것을 v1.40 '인식했지만 빠진 머리'로 되살린 것.

**우리가 못 잡은 이유:** ① 미인식 잉크 찾기 — G♯4 잉크가 F♯4 인식 상자(+여유) 안이라 '이미 인식됨'으로 처리. ② 박자 검사 — 오른손 성부가 모두 짧지만(2·1.5·2박) 박 위치가 맞고 그 보표에 '설명 안 되는 머리'가 없어 '쉼표 생략' 관례(_omitted_rest_voices)로 정상 처리.

**검토한 방법과 결과:**
| 방법 | 내용 | 결과 |
|---|---|---|
| A. 머리 둘레 훑기 | 인식된 머리 위·아래·2도 옆자리에서 빈 머리 모양 잉크 찾기(`ink_check.scan_missing_chord_heads`, `_ring_all_around` — 코드는 남김, 호출 안 함) | 느슨한 판정: 교회 135곳·4쪽 40곳 오탐. 엄격한 판정(오선 행 제외·8방향 중 6방향+좌우): 교회 12곳 오탐(검정 화음 머리 사이 빈칸·빔 사이·Audiveris가 옮겨 둔 온음표 상자), 기도 2마디 새 오류, **정작 9마디는 놓침** → 미적용 |
| B. 설명 안 되는 기둥 | 인식된 어느 기둥(src_stem)으로도 덮이지 않는 세로선을 빠진 음 증거로 → 쉼표 생략으로 봐주지 않음(`ink_check.mark_unexplained_stems` — 코드는 남김, 호출 안 함) | 교회 56마디 중 51마디에서 잡힘(이웃 보표 기둥, 가사 'ㅣ' 획, 묶음괄호, 머리와 이어지지 않은 인식 기둥) → 정상 마디들이 오류로(교회 2·18·37, 기도 55, 데모 4·11 등) → 미적용 |
| C. B를 좁힘 | 한 머리에서 기둥이 **위·아래 동시에** 뻗는 모양만 찾기 | **v2.70 적용** — `ink_check.find_hidden_voice_stems`. 시험 악보 6종 중 감지는 교회 9마디 하나(정답), 오탐 0 |
| D. 다른 성부에 음 넣기(수동 편집) | 음표를 고르고 '같은 자리·반대 기둥·다른 성부'로 음 넣기(길이는 음표 칸, 넣은 뒤 ↑↓) | 미구현. 지금은 이 음을 넣을 방법이 없음(화음 추가는 같은 성부·같은 길이). 버튼 자리: 동작 칸 '앞/뒤 삽입'을 하나(메뉴)로 합치는 안 |
| E. Audiveris 다시 실행 | 그 쪽을 더 높은 해상도로 | 느리고 빈 머리를 찾는다는 보장 없음 |
| F. 쉼표 생략 규칙 엄격화 | 피아노 보표 앞쪽 빈 박은 봐주지 않음 | 원본이 실제로 쉼표를 생략한 마디(기도 2마디 등)까지 오류 → 부작용 큼 |

**v2.40 해결(수동 경로):** '원본에서 넣기'(원본 이미지에서 G♯4 머리를 두 번 클릭)로 9마디가 바로 해결된다 — 음높이 G♯4, 빈 머리 → 2분음표, 위 기둥 → 위 성부(성부 3), 마디 검사 정상(위 성부 4박). 자동 찾기(C안)는 여전히 보류.

**결정을 미룬 이유(사용자):** 어느 자동 방식도 개선이 아니라 후퇴(오탐·정상 마디 오류)가 될 수 있다. 다시 다룰 때 이 기록을 바탕으로 방식을 고른다(추천 순서: D → C).

## 1. 프로젝트 개요

- **무엇:** 악보 이미지·PDF를 인식해 편집 가능한 악보로 바꾸고, 원본과 나란히 보며 고친 뒤 MusicXML·MIDI로 내보내는 데스크톱 프로그램.
- **누가 쓰나:** 선린인터넷고 음악 선생님, 다른 학교 음악 선생님들(실사용 피드백을 받아 개선 중).
- **인식 엔진:** Audiveris 5.11.0(오픈소스, Java). 우리 프로그램은 Audiveris 결과(.omr + .mxl)를 읽어 화면 표시·편집·재생·내보내기를 담당.
- **기술:** Python 3 · PySide6(화면) · OpenCV · NumPy · Pillow · pypdfium2(PDF) · 내장 신스(재생) · PyInstaller(onedir) · Inno Setup(설치 파일).
- **라이선스:** AGPLv3(Audiveris가 AGPL이므로 함께 배포 시 AGPL).

## 4. 처리 흐름

1. **열기:** 이미지 또는 PDF.
   - PDF는 **1페이지만** 400dpi로 그림 변환(여러 페이지는 v2.00 예정).
   - 경로에 한글이 있으면 영문 임시 사본으로 Audiveris에 넘김.
2. **캐시 확인:** 입력 그림 내용의 해시로 `%LOCALAPPDATA%\Sprouty\omr_cache\<키>`를 찾고, 있으면 Audiveris를 건너뜀(최근 60개 보관). 데모곡 결과는 `resource_dist/omr_cache`에 동봉.
3. **Audiveris 실행**(뒤 스레드, 대기 화면 표시) → `.omr` + `.mxl`.
4. **merge:** .omr의 위치·신뢰도 + .mxl의 음악 내용을 합쳐 ctx 생성. 파트·성부·화음 짝짓기, 각종 신뢰도 필터 적용.
5. **PDF 글자 레이어:** 제목·작사작곡·빠르기말, 가사(보표별·절별), 나머지 글자(Andante, Piano, 절 번호, 저작권 문구) 추출. 악보 전용 글꼴 문자와 보이지 않는 글자는 제외.
6. **모델:** Score 생성 → 유령 쉼표 정리 → 가사 붙이기.
7. **화면:**
   - 배치 → 그리기(원본의 F배 크기 이미지).
   - 축소 피라미드: 진한 픽셀을 남기는 2·4·8·16배 축소본을 뒤에서 만들어, 화면 맞춤에서도 오선이 선명하게 보임.
8. **편집 · 재생(WAV 합성) · 내보내기(MusicXML/MIDI).**

## 5. 핵심 설계 결정과 근거 (다시 고민하지 않도록)

### 5.1 원칙
- **내부 키와 화면 문구 분리:** 화면에 보이는 문구를 내부 상태값이나 비교 기준으로 쓰지 않는다(다국어 대비). 셈여림·잇단 메뉴 등은 내부 키 → 표시 문구 사전으로 관리.
- **Audiveris가 맞게 읽은 것은 그대로 표현, 못 읽는 것은 편집 기능으로 보완.**
- 수정할 때마다 **실제 악보로 원본과 나란히 비교 이미지**를 만들어 확인하고, 회귀 검사(72/84) 유지를 확인한다.

### 5.2 인식 결과 필터·보정 (수치는 실측 근거)

| 항목 | 규칙 | 근거 |
|---|---|---|
| 셈여림 | 신뢰도(grade) < 0.6 제거 | 교가의 허위 셈여림 6개 → 0 |
| 셈여림 + PDF 글자 | 글자와 겹치면 제거. **단, 겹친 글자가 그 셈여림 자체(p, mf…)면 유지** | "봄이 오면"은 *p*를 글자로 넣음 |
| 붙임줄 | 신뢰도 < 0.5 제거, 곡선↔음표머리 관계 우선 | 허위 붙임줄 제거 |
| 잇단음표 | **ctx-grade** < 0.8이면 잇단으로 보지 않음 | 진짜 0.845~0.914 / 교가 가짜 "3"(가사 "세" 오인) 0.736 |
| 유령 쉼표 ① | 성부에 쉼표 하나뿐 + 다른 성부 음표와 같은 x → 삭제 | 교가 5마디 |
| 유령 쉼표 ② | 오선 밖 1칸 이상 + 음표 기둥 옆 + 8분 이하 → 삭제(8분음표 꼬리 오인) | "봄이 오면" 19마디 |
| 유령 쉼표 삭제 시 | 붙어 있던 쐐기·셈여림은 같은 보표의 가장 가까운 음으로 옮김 | "봄이 오면" 22마디 왼손 디크레셴도 |
| 온마디 쉼표 | .omr에 위치가 없고 .mxl에만 있으면 마디 가운데에 생성 | "봄이 오면" 7~8마디 |
| 끝 없는 쐐기 | .omr 실제 쐐기 길이 안의 마지막 음을 끝으로 | "봄이 오면" 22마디 |
| 쐐기 좌표 배정 | 같은 줄 안 후보를 비용(가로 + 0.2×세로) 낮은 순으로 1:1 배정 | 노래·피아노 쐐기가 같은 x일 때 |

### 5.3 여러 파트·보표
- 파트는 **.omr의 논리 파트 id**로 MusicXML 파트와 짝짓는다(시스템 안 순서가 아님). 피아노만 있는 도입부 줄이 노래 파트로 잘못 짝지어지던 문제.
- 음자리표는 보표마다 Audiveris 인식값(보표 머리의 clef → TREBLE/BASS)을 쓴다. 예전의 "보표2 이상은 낮은음자리표" 고정 규칙은 폐기.
- 중괄호와 마디선은 **같은 파트 단위로** 묶는다(노래 보표는 따로).
- 가사는 **보표마다** 그 바로 아래 영역에서 찾고 그 보표 음표에만 붙인다. 절 번호(1. 2.)와 셈여림 글자는 제외.

### 5.4 화음·성부
- 화음 구성음 짝짓기: .omr 머리와 .mxl 음을 **둘 다 낮은 음부터 정렬**해 짝짓는다(정렬 방향이 반대였던 버그 → 비킨 머리·임시표가 엉뚱한 음에 붙음).
  - 화음 단위 표시(셈여림·쐐기·이음줄)는 화음 전체에서 모은다.
- 화음 기둥은 **화음마다 하나**만 그린다(빔 없는 화음, 빔 속 화음 모두). 기준은 비키지 않은 머리 열(가장 많은 x)이고, 반대쪽 끝 음을 넘어 뻗는다.
- 화음 기둥 방향: 가운데 줄에서 가장 먼 음의 반대로. **위아래 같으면 아래로**.
- 마디 검사 성부 규칙:
  - 혼자뿐인 성부(요소 1개)는 보정한다.
  - 성부 합이 정확히 맞으면 한 성부로 본다.
  - **생략 쉼표 관례:** 같은 보표에 마디를 채운 성부가 있으면, 그보다 짧은 다른 성부는 쉼표가 생략된 것으로 본다. 넘치는 성부는 계속 오류.
- 잇단음표 그룹: 같은 보표 안에서 묶되, **다른 성부의 일반 음표에서 끊기지 않게** 건너뛴다.

### 5.5 그리기 규칙
- 잇단 숫자:
  - **빔으로 묶인 그룹**은 괄호 없이 빔 쪽에 숫자만.
  - **빔 없는 그룹**은 괄호 + 숫자를 기둥 쪽에. 그 보표에 가사가 있으면 항상 위쪽.
  - 음표머리·기둥 끝·오선 중 가장 바깥 것에 바짝 붙인다.
- 늘임표: 맨 위 장애물(머리·기둥 끝·오선 윗줄) 바로 위.
- 글자 크기: PDF 글자 높이 ÷ 0.92(나눔고딕 실제 글자 높이 비율). 굵은 글꼴은 테두리로 굵게.
- 축소 표시: 진한 픽셀 보존 피라미드. 오선 굵기는 v1.10에서 0.09칸(덧줄 0.11칸)으로 되돌렸다.
- **다성부(v1.10):** 한 마디·한 보표에서 서로 다른 성부의 음이 같은 자리(0.8칸 이내)에 있으면 '동시 진행 성부'로 본다.
  - 방향은 **실제로 겹치는 상대 성부와 비교**해 정한다: 같은 자리 음끼리 더 높은 쪽에 +1, 낮은 쪽에 −1을 모아 양수면 위, 음수면 아래(동률이면 평균 음높이가 가장 높은 성부가 위). Audiveris는 위 선율을 마디 중간부터 새 성부 번호로 잇기도 해서("기도의 능력" 2마디 성부 3), 곡 평균만 보면 틀린다. 빔·화음 기둥·잇단 숫자·이음줄·늘임표가 이 방향을 따른다(아래 성부 늘임표는 오선 아래 거꾸로).
  - 그 성부의 쉼표는 원본에 찍힌 높이로(반대쪽이면 관례 자리 ±2칸).
  - 같은 자리 겹침이 없는 성부는 예전처럼 음높이로 정한다 — Audiveris가 잇단음표 안 음마다 성부 번호를 달리 매기는 경우를 잘못 다성부로 보지 않기 위해서.
  - 빔은 원래 성부별로 묶여 있었고, 두 성부가 같은 방향으로 그려져 겹쳐 보인 것이 원인이었다.
- **겹점(v1.10):** `Element.double_dot`(dotted도 True), 길이 ×1.75. 점 버튼/`.`은 없음 → 점 → 겹점 → 없음 순환.
- **음자리표 변경(v1.10):** MusicXML `<clef>`의 마디 안 위치를 그대로 읽어, 바뀐 뒤 첫 요소에 `Element.clef_change`를 붙인다. 화면은 (마디 번호, x) 기준으로 그 뒤 음의 높이를 새 음자리표로 계산하고, 바뀌는 음 바로 앞에 75% 크기 음자리표를 그린다. 줄 머리 음자리표는 .omr 값. 요소를 지우면 변경은 같은 보표 다음 요소로 넘어간다.
- **조표 바뀜(v1.10):** `Score.fifths`는 곡 처음 조표(예전엔 마지막 `<key>`로 덮여 곡 전체가 끝 조표였다), `Measure.key_change`는 바뀌는 마디. 줄마다 그 줄 조표를 머리에 그리고, 줄 중간에서 바뀌면 그 마디 앞에 새 조표(다장조로 가면 제자리표로 취소). 조바꿈은 중간 조표도 같은 음정만큼 옮긴다.
- **빠르기 ♩(v1.10):** 악보 글꼴 문자 중 음표 모양(SMuFL 메트로놈·음표, Maestro/Opus의 q·e·h, 이름 없는 내장 기호 글꼴의 U+F0xx — "기도의 능력"은 U+F047)만 따로 모아, 빠르기 줄 '=' 바로 왼쪽에 있으면 ♩·♪ 등으로 되살린다(점음표 포함). 그릴 때는 Bravura 메트로놈 글리프로 그린다.

### 5.5.1 기둥·빔 방향과 빔 기울기 (v1.40)
- **방향 원칙:** ① 성부 하나 — 가운데 줄에서 가장 먼 음의 반대쪽으로(동률이면 아래로), 빔 묶음은 묶음 전체로 판단. ② 두 성부 이상이 같은 자리에 있으면 위 성부는 위로·아래 성부는 아래로(v1.10). v1.40: 1도·2도로 옆에 비켜 찍힌 머리(나란히 놓인 같은 음)는 2.6칸까지 '같은 자리'로 본다("교회" 3마디 왼손 8분음표 A2와 온음표 A2 — 두 성부를 못 알아봐 ①이 적용되어 빔이 원본과 반대였다).
- **빔 기울기:** 첫 음과 끝 음(화음은 빔 쪽 음)의 높이 차이의 3/4, 최대 2.5칸. 가운데 음이 양 끝보다 빔 쪽으로 튀어나오면(오목) 수평. 기둥은 모두 최소 길이 이상(기울어진 선에서 가장 짧은 기둥 기준으로 평행 이동). 빔은 평행사변형으로 그린다(2차 빔·짧은 빔 포함).

### 5.5.2 하단 편집 막대 (v1.41)
- 모든 버튼 높이 30px(`EDIT_BTN_H`)로 통일. 점 버튼은 점(•)만, 크레셴도/디크레셴도는 글자 없이 긴 부등호 아이콘, 늘임표 버튼(U) 추가. (전체 재구성은 v3.00)

### 5.6 MusicXML 내보내기 (v1.20)
- **파트:** Audiveris 논리 파트(`score.staff_parts`)마다 `<part>`, 이름도 Audiveris 것(Voice·Piano 등). `build_from_context`가 `score.staff_parts·staff_clefs·part_names`를 Score에 붙여 둔다.
- **보표:** 파트의 보표 수 = 그 파트가 가장 많은 보표를 가진 줄 기준. 보표가 적은 줄(예: 합창이 한 줄은 SA, 다른 줄은 TB)은 음자리표가 맞는 자리에 배정하고, 빈 보표는 온마디 쉼표(`<rest measure="yes"/>`).
- **성부 시간 배치:**
  - 마디 처음에서 시작하는 성부는 0에 놓는다.
  - 늦게 시작하는 성부는 같은 자리(x, 머리 폭 0.8배 이내)에 있는 음의 박 위치에서 시작한다. 없으면 앞뒤 음 사이를 x 비율로 나누고 1/48박 격자에 맞춘다.
  - 성부가 마디 안에 들어가는 길이면 마디를 넘지 않게 시작점을 당긴다.
  - **이어지는 성부:** 앞 성부가 끝난 오른쪽에서 시작하고 둘을 합치면 마디가 꼭 차면 앞 성부 끝에서 시작한다("기도의 능력" 2마디 성부 1+3).
  - [v1.32] 마디를 채운 성부가 없는 보표(예: 왼손 3박째 2분음표 하나)는 **다른 보표의 같은 자리 박 위치**에서 시작한다(`measure_anchors` — 이어지는 성부를 합친 '빈틈 없이 마디를 채운 줄'이 기준). 마디 검사와 같은 기준.
  - 시간이 겹치지 않는 성부는 한 성부로 합친다. 겹치면 높은 음 성부가 voice 1이고, 두 성부 이상인 마디는 `<stem>` up/down을 적는다.
- **그 밖:** 화음(빔은 첫 음에만 — Verovio가 구성음 빔을 거부), `<tie>`는 `<duration>` 뒤(규격 순서, v1.00은 반대), 가사 늘임 표시(– — _ ~)는 음절로 내보내지 않음, 셈여림·쐐기는 해당 성부·보표의 `<direction>`, 조표·박자표·음자리표 바뀜(마디 중간 포함), 줄바꿈 `<print new-system>`.
- **검사(`tools/check_musicxml.py`):** ① backup/forward 시간 흐름(음수·정상 마디 넘침) ② 마디별 음 목록이 모델과 같은지 ③ 붙임줄·이음줄·가사 수 ④ music21로 읽어 정상 마디 길이가 박자와 같은지. 추가로 Verovio로 조판해 오류 메시지가 없는지 확인했다(남는 것은 온마디 쉼표의 길이 경고 1건, 무해).

### 5.7 마디 검사 — 생략 쉼표 판정 (v1.30 재설계)
- 마디를 못 채운 짧은 성부를 '쉼표를 생략한 성부'로 봐주는 조건(모두 만족):
  1. 그 성부의 음들이 같은 줄의 **마디를 채운 성부 음들과 박 위치가 맞는다**(다른 보표도 기준 — 세로 정렬은 줄 전체가 같다). 같은 자리 = 머리 폭 1.1배 이내(2도로 비킨 머리 포함). 시작 위치는 첫 음과 같은 자리의 기준 음 박.
  2. 그 보표의 원본 그림에 **인식되지 않은 음표 머리가 없다**(`ink_check`).
  3. 그 보표에서 '혼자뿐인 음이라 버려진 성부'가 없다(이어지는 성부로 합쳐진 것은 제외).
- 예: "기도의 능력" 2마디 왼손(3박째 2분음표 하나, 원본도 앞 쉼표 없음)·오른손 아래 성부(1~2박) → 정상. 같은 마디에서 점이 빠지면 뒤 음 박이 어긋나 오류로 남는다. "교회" 7마디(가운데 음 누락)·9·11마디(원본에 머리가 있는데 인식 안 됨)·데모곡 11마디(음 셋이 버려짐) → 오류.
- v1.20의 '마디 처음보다 늦게 시작하는 성부만' 규칙은 뒤쪽 쉼표 생략과 다른 보표 기준을 놓쳐 폐기.

### 5.7.1 미인식 보완 (v1.40, `omr_bridge/ink_check.py`)
- **찾기(방법 B):** 원본 잉크 − Audiveris가 인식한 '낱 기호' 상자(.omr inter bounds: 머리·기둥·빔·점·임시표·쉼표·음자리표…) − 오선(가로 2칸 이상) − 가는 곡선. 묶음 상자(head-chord·beam-group·key·time-pair)·이음줄·쐐기·덧줄 상자는 쓰지 않는다(넓게 덮어 빠진 기호를 가리거나, 덧줄은 빠진 머리를 위아래로 잘라 버림). 오선·덧줄을 지운 자리는 세로로 얇게 다시 잇는다.
  - 방법 A(편집 악보 그림과 원본을 겹치기)는 실험 후 기각: 글꼴·빔 두께·가사 글꼴 차이가 잡음, 위치 오차를 흡수하려 넓히면 머리 옆 점·2도 머리가 묻힘.
  - 분류: 머리(0.7~2.9칸 × 0.6~1.6칸, 꽉 찬 타원 55% 이상, 세로 획 둘이 꿰뚫으면 ♯·♮이라 제외 — 획 하나는 2도 음의 위·아래 기둥일 수 있어 남김) / 점(0.75칸 미만, 오선 ±1칸, 이음줄 상자 안 조각 제외) / 기타.
  - **Audiveris가 머리로 인식했지만 음악에서 뺀 머리**(편집 모델에 없는 head inter)도 빠진 머리로 더한다("교회" 9마디 F♯4).
- **제안 음표:** 음높이(세로 위치 + 그 자리 음자리표·조표) · 박(같은 줄 '마디를 채운 줄'의 같은 자리, 1·2도로 옆에 비킨 머리는 바로 왼쪽 이웃 음의 박) · 길이(검정/빈 머리 + 그 보표의 다음 박까지 — 성부 번호와 무관) · 성부(원본에서 찾은 기둥 방향: 위 → 높은 성부부터) · 같은 박에 음이 있으면 화음 구성음. **자동으로 넣지 않는다** — 주황 음표로 보여 주고 클릭 → Enter 넣기 / Delete 무시(실행 취소 가능). 원본 패널에는 주황 점선.
- **성부 다시 나누기(`editing.repair_voices`):** 제안을 넣은 마디에서, 음마다 박을 '같은 자리' 기준으로 정하고 시간 순으로 성부를 다시 배정(이어지는 성부 → 원래 성부 → 빈 성부). 마디 검사가 정상이 될 때만 반영. ("교회" 5마디: 아래 성부 E4가 위 성부 2분음표 뒤에 붙어 있던 것)
- **[v1.41] 자동 보완:** 불러올 때 마디마다 그 마디의 제안을 함께 넣어 보고, 마디 검사가 정상이 되면 그대로 둔다(정보에 목록). 정상이 안 되면 되돌려 주황 제안으로 남긴다(`ink_check.auto_apply`). "교회" 1p는 불러오자마자 **16/16 정상**.
- 실측: "교회" 1p 제안 5개(5·7·9·11마디 오른손 + 9마디 왼손 E3) 모두 실제 누락 → 모두 넣으면 **16/16 정상**. 남는 한계: 9마디 오른손 G♯4 2분음표(빈 머리가 F♯4 머리 상자에 덮임)는 직접 넣어야 함. 다른 시험 악보는 제안 0~1개(4p 7마디 화음 구성음 — 실제 누락).

### 5.7.1.1 재생 시각 (v1.41, `midi.py`)
- 예전: 성부마다 '목록 순서대로 길이를 더해' 시각을 정함 → 편집으로 넣은 음(목록 끝에 붙음)·앞 쉼표를 생략한 성부가 엉뚱한 때 울림(데모곡 11마디는 오른손 4음이 한꺼번에 울렸다).
- 이제 내보내기·마디 검사와 같은 박 배치(`musicxml.element_onsets` — 같은 줄의 마디를 채운 줄 기준)로 각 음의 시작 시각을 정한다. 2도로 옆에 비켜 그려진 음도 같은 박이면 동시에 울린다. 깨끗한 단선율 악보(syn05)는 예전과 한 음도 다르지 않음.

### 5.7.1.2 늘임표 신뢰도 (v1.41)
- "교회" 7마디: 가사 '랑'을 FERMATA_BELOW(0.224)로 오인 → 원본에 없는 늘임표. .omr 늘임표 inter의 신뢰도가 0.5 미만이면 버린다(fermata-chord 관계로 화음과 짝지음). 늘임표는 선택 후 U 키나 편집 막대의 늘임표 버튼으로 붙이고 지운다.

### 5.7.1.3 이음줄·셈여림 오인식 정리 (v1.42)
- **이음줄 신뢰도:** 짝(시작·끝 음) 가로 범위와 겹치는 slur inter 중 가장 맞는 것의 신뢰도가 0.3 미만이면 버린다("교회" 13→14마디 합창: 가사 글자 조각 SLUR_BELOW 0.193).
- **셈여림:** ① 원본에서 그 기호(dynamics inter)를 찾지 못하면 버린다(근거 없음 — 13마디 f 0.231). ② **노래·합창 파트 보표의 아래**(맨 아랫줄 + 0.5칸 아래)에 있는 셈여림은 가사 글자 오인으로 보고 버린다(9~11·14마디 합창 p, 신뢰도 0.6~0.7이라 신뢰도로는 못 거름). 노래 파트 셈여림은 보표 위에 쓰는 관례. 노래 파트 판정은 파트 이름(Voice·Choir·Soprano…·합창·노래 등, `merge._is_vocal`).
- **빠진 이음줄 되살리기(`ink_check.recover_slurs`):** 편집 악보의 어느 이음줄에도 쓰이지 않은 slur inter를 이웃 조각끼리 합치고(틈 1.5칸), 최고 신뢰도 0.5 이상·양 끝이 같은 보표 음표 머리에 닿으면 이음줄(같은 음이면 붙임줄)을 넣는다. 3칸보다 높은 곡선(보표를 건너는 이음줄)은 제외. 이미 쓰인 조각은 합치기 전에 뺀다(이어진 붙임줄 둘을 긴 곡선 하나로 착각하지 않게). "교회" 1p: 14마디 왼손·5마디 오른손 되살림.
- **내보내기 이음줄 번호:** 이음줄마다 번호(1~6)를 따로 매긴다 — 한 음에서 이음줄 둘이 시작하는 경우("교회" 5마디 G♯4)가 하나로 합쳐지던 문제.
- **주황 점선:** 인식된 이음줄 상자 안의 잉크는 '미인식'으로 표시하지 않는다(13마디 첫 이음줄 오표시).
- **빔:** 최대 기울기 tan 0.2(약 11°), 두께 0.42칸·간격 0.68칸.

### 5.7.1.4 앞꾸밈음 찾기 (v1.43, `ink_check.find_graces`)
- Audiveris는 꾸밈음(작은 머리)을 전혀 읽지 못한다("교회" .omr에 작은 머리 0개). 음표마다 바로 왼쪽(0.3~3.4칸)의 **원본 그림**에서 오선·세로선을 지우고 남는 작은 타원을 후보로 보고 다음을 모두 만족하면 꾸밈음:
  - 크기 폭 0.62~1.1칸·높이 0.5~0.85칸·꽉 찬 타원, 인식된 음표 아님, 가장 가까운 보표가 본음의 보표, 확실히 인식된(0.5↑) 음자리표·임시표·마디선·박자표 상자 밖
  - 홀로 떨어짐(0.35칸 테두리 잉크 12% 이하 — 오선·기둥 자리 제외), 오른쪽 끝에서 위로 짧은 기둥(1.1칸 구간 50% 이상, 전체 2.8칸 이하), 머리 바로 위 잉크 20% 이하(빗금 ~0.12는 통과, 꼬리 끝·음자리표 0.4↑), 기둥이 아래로 이어지지 않음(♯·마디선), 왼쪽 잉크 밀도 35% 이하(빔 끝), 기둥 꼭대기 오른쪽 1.1칸 안에 0.35칸 두께 띠 없음(빔)
  - 본음 = 같은 보표에서 바로 오른쪽 음. 이음줄: 인식된 곡선이 있거나 원본에서 꾸밈음~본음 위를 가로지르는 곡선(열 70% 이상)이 있으면 함께 넣는다.
- 실측: "교회" 1p 1·2·13·15마디 꾸밈음 4개(음높이·본음·이음줄 모두 원본과 같음), 다른 시험 악보 5개 오탐 0.
- **화면:** 주황 작은 음표(기둥·빗금)로 표시하고 **클릭하면 바로 넣는다**(본음 앞 8분 꾸밈음 + 이음줄). 잘못 넣으면 선택 후 삭제·Ctrl+Z. 꾸밈음은 박자를 차지하지 않아 '마디가 맞으면 자동 넣기'에서 제외.

### 5.7.1.5 숨은 박자 오류·약한 임시표 (v1.43)
- **같은 방향 기둥 규칙(`editing._same_stem_lone_conflict`):** 음 하나뿐인 성부의 음이, 같은 보표에서 마디를 채운 성부의 '같은 방향 기둥' 음이 울리는 도중에 시작하면 박자 오류(진짜 두 성부라면 기둥이 반대). 원본 기둥 방향은 불러올 때 `e.stem_dir_img`로 적어 둔다. ("교회" 15마디 왼손: 빔을 놓쳐 G♯2가 4분음표로, E3가 혼자 다른 성부로 — 4분음표 덕에 마디가 맞아 보였다)
- **편집 뒤 성부 다시 나누기:** 편집한 마디가 정상이 아니거나 한 보표에 '음 하나뿐인 성부'가 따로 있으면 `repair_voices`(정상이 될 때만 반영). 15마디는 G♯2·E3를 8분음표로 고치면 한 성부로 합쳐져 박 위치까지 원본과 같아진다.
- **약한 임시표:** 신뢰도 0.5 미만이고 조표만으로 같은 음높이(소리 영향 없음)인 임시표는 지운다(같은 마디 앞 음에 다른 임시표가 있으면 남김). "교회" 16마디 B3의 ♮(너비 2px, 0.367).
- **임시표 버튼(A):** ♯ → ♭ → ♮ → 없음(기호 지우고 그 마디 조표의 음높이로) 순환.

### 5.7.1.6 꾸밈음 기둥·빔 묶기 (v1.44 → v2.00에 포함)
- 꾸밈음 기둥은 음높이와 상관없이 **항상 위로**(조판 관례). 예전엔 보통 음표 규칙을 따라 높은 꾸밈음이 아래로 그려졌다.
- **빔으로 묶기/풀기(`editing.toggle_beam`, 빔↻ 버튼·키 7):** 음표 여러 개를 고르면 한 빔으로 묶고(화음 구성음 함께), 이미 한 빔이면 푼다. 1개 선택이면 예전처럼 빔그룹 박자 순환. ("교회" 15마디 왼손 G♯2–E3: Audiveris가 빔을 아예 못 읽음 — .omr에 빔 inter 없음. 빔이 없으니 두 음이 각자 음높이 규칙을 따라 꼬리 방향이 달랐던 것)

### 5.7.2 붙임줄을 쉼표로 오인 (v1.30, `editing.fix_tie_rests`)
- Audiveris가 짧은 붙임줄을 2분쉼표로 읽음("교회" 14마디, HALF_REST 신뢰도 0.52). 2분·온쉼표 + 높이 0.7칸 이하 + 같은 성부 바로 앞뒤 음이 같은 음높이 + 쉼표를 빼면 마디가 꼭 참 → 쉼표를 지우고 붙임줄로.

### 5.7.3 스타카토로 오인한 부점 (v1.32, merge.py)
- "기도의 능력" 2마디 아래 성부 F4의 부점을 Audiveris가 STACCATO(0.779)로 읽음(부점 inter 없음 — 확인함).

### 5.7.4 마디 검사 보정 (v1.20)
- 마디를 채운 성부가 없을 때, **이어지는 두 성부**(앞 성부 마지막 음보다 오른쪽에서 시작 + 합이 마디 길이)는 한 성부로 본다.
- **생략 쉼표 관례는 '마디 처음보다 늦게 시작하는' 짧은 성부에만** 적용한다(머리 폭 1.3배 — 2도로 비킨 머리 포함). 마디 처음부터 시작했는데 짧은 성부는 음이 빠진 것이다("교회" 7마디). 이 보정으로 v1.10 시험 악보에 있던 실제 리듬 실수(겹점 2분 + 16분 = 3.75박)도 잡혔다.

### 5.8 Audiveris 찾기 (v1.21)
- 실행할 때마다 다시 찾는다(프로그램을 켠 채 폴더를 옮겨도 된다). 순서: 환경 변수 `AUDIVERIS_BIN` → 설치 폴더 `audiveris\` → 프로그램 폴더와 **나란히** 있는 `audiveris\`(권장) → 프로그램 폴더 안 → **한 단계 위 작업 폴더의 다른 폴더들**의 `audiveris\`(예: `pythonWorkspaces\OMREditor\audiveris\`) → Program Files 등 공식 설치 위치.

### 5.9 화면 그림 메모리 (v1.31)
- 실사용 `MemoryError`(편집 악보 표시 단계). 교회 1p 기준 그림 6264×8426(158MB)을 RGB 변환 → tobytes(조립 중 2배) → QImage 복사 → QPixmap으로 4~5번 복사해, 다시 그릴 때마다 +790MB가 순간적으로 필요했다(평소 650MB → 최고 1,439MB).
- 이제 numpy 배열 하나를 512줄 띠 단위로 채우고, 화면(QImage, `drawImage`)과 축소본이 그 배열을 그대로 함께 쓴다. 새로 그리기 전에 이전 그림·축소본을 먼저 놓아준다(`release_render`). 실측: 평소 447MB, 최고 859MB.
- 그래도 메모리가 모자라면 배율(F)을 한 단계씩 낮춰 다시 그리고 상태 표시줄에 알린다(오류 창 없음).

### 5.10 로딩·재생·기타

  - 종료 시 임시 WAV 정리.
- 한글 경로: `cv2.imread` 대신 `np.fromfile + cv2.imdecode`. Audiveris에는 영문 임시 사본을 넘긴다.
- 안내 팝업은 없애고, 인식 안내는 "정보" 대화상자에서 본다.

## 5.9 여러 페이지 (v2.00)

### 흐름
1. **페이지 그림(`BookJob.prepare`)**: PDF 각 쪽을 한 페이지 경로와 똑같이 400dpi로 그리고 여백을 자른다(pageN.png, 자른 위치 meta.json) → **여러 장 TIFF** 하나(book.tif, OpenCV로 저장 — Pillow의 libtiff 저장은 큰 그림에서 오류).
   - PDF를 Audiveris에 그대로 넘기면 PDFBox로 다르게 그려 결과가 달라졌다("교회" 1쪽 피아노 3마디가 MusicXML에서 빠짐). 같은 그림을 넘기면 한 페이지 경로와 결과가 같다.
2. **장 단위 인식(`process_sheet`)**: 1장은 `-sheets 1 -save -export -- book.tif`, 2장부터 `-sheets N ... -- book.omr`(시간 정보·파트 구성이 이어짐, 한 장 약 55~80초). 실행마다 그 장의 MusicXML만 내보내므로 sheetN.mxl로 보관. 캐시: `%LOCALAPPDATA%/Sprouty/omr_cache/book_<PDF 해시>/`.
3. **페이지 모델(`page_builder.build_page`)**: 장마다 지금까지 검증한 한 페이지 처리(유령 쉼표·붙임줄 오인·미인식 잉크·이음줄 되살리기·자동 보완·기둥 방향·꾸밈음·가사)를 그대로. merge·ink_check는 `sheet` 번호를 받아 그 장의 .omr을 읽는다.
4. **잇기(`book.append_page`)**: 세로 좌표 += 앞 페이지 높이 합, 줄 번호·마디 번호 이어 붙이기, `measure.page` 기록. **파트**는 시트 기준 번호 → book.xml의 논리 파트(logical-id)로 바꿔 곡 전체에서 같은 번호(예: "교회" 1장 = 합창1+피아노, 2장 = 합창2+피아노 → 파트 [Voice, Voice, Piano]). 조표·박자표가 앞 페이지와 다르면 그 페이지 첫 마디에 바뀜으로 넣는다.
5. **편집기**: 1장이 끝나면 바로 보여 주고(대기 화면은 1장 동안만), 나머지 장은 뒤 스레드에서 차례로 인식해 `_bookPage` 신호로 곡 끝에 잇는다. 이때 **되돌리기 기록의 모든 사본에도 같은 페이지(깊은 복사)를 덧붙여** 되돌려도 페이지가 사라지지 않는다. 다른 악보를 열면 세대 번호로 이전 뒤 작업 결과를 무시.
6. **그리기**: 곡 전체 레이아웃(클릭 판정용)에서 **지금 페이지만** 그린다 — `layout.page_view(layout, dy)`로 세로 좌표를 옮긴 사본 + 페이지 크기 캔버스 + 패널의 그림 위치(`img_dy`). 원본 패널도 지금 페이지 그림만 올린다(메모리는 페이지 수와 무관하게 한 페이지만큼).
7. **페이지 이동**: 왼쪽 점(인식 중인 페이지는 점선 테두리·툴팁 '인식 중'), PgUp/PgDn, '화면 맞춤'은 지금 페이지에. 아직 인식 중인 페이지를 누르면 안내만.
8. **MusicXML**: 페이지가 바뀌는 마디에 `<print new-page="yes">`.

### v2.01 — 유령 머리·제안 음표 강화
- **유령 머리 지우기(`ink_check.drop_phantom_heads`)**: Audiveris가 빔·붙임줄이 겹친 자리를 머리로 읽은 것("교회" 19마디 왼손 'B3', 신뢰도 0.295 — 그 쪽에서 가장 낮음; 빔 inter는 아예 없음 → A2·E3가 4분음표로). 신뢰도만으로는 못 가른다(4쪽 촘촘한 화음은 0.16~0.40인데 진짜). **신뢰도 < 0.4 + 원본 잉크**로 판정: 검정 머리는 안쪽 타원 잉크 0.8 미만(확실한 머리 1,200여 개는 모두 1.0, 진짜 저신뢰 머리 0.84~1.0, 유령 0.65~0.69), 빈 머리는 안쪽 < 0.15·테두리 < 0.6. 화음 구성음은 바로, 혼자 있는 음은 마디 검사가 나빠지지 않을 때만 지운다. 지운 머리는 'Audiveris가 찾고 뺀 머리' 후보에서도 뺀다(안 그러면 다시 제안·자동 보완됨). 19마디는 빔 자체가 인식되지 않아 여전히 '부족' — A2·E3를 8분음표로 + 빔 묶기(7)로 고친다.
- **머리 잉크 검사(`_is_head_ink`)**: 미인식 잉크·빠진 머리 후보는 모두 진짜 머리 모양이어야 한다 — 검정은 안쪽 ≥ 0.9, 빈 머리는 안쪽 < 0.5·테두리 ≥ 0.6·키 ≥ 0.85칸. 이음줄 가운데 굵은 부분·악센트 조각(안쪽 0.34~0.74) 오탐 6개를 막았다.
- **이미 정상인 마디도 자동 보완**: 화음 구성음·다른 성부 음은 박 합계를 바꾸지 않아 예전엔 '넣으면 정상이 되는' 기준에 걸리지 않았다. 이제 넣은 뒤에도 정상이면 둔다("교회" 5쪽에서 실제 누락 10개 자동, 오탐 0).
- **제안 음표의 성부**: 빠진 머리의 기둥이 겹치는 음과 반대 방향이면 화음이 아니라 다른 성부(4분·2분음표)로 넣는다("교회" 18마디 오른손: 위로 기둥 G♯4 4분음표 + 아래로 기둥 F♯4·E4 8분음표). 기둥 방향(`assign_stem_dirs`)을 제안 전에 먼저 구한다.
- 한 페이지 경로(편집기·검증 도구)도 `page_builder`를 쓴다 — 처리 단계가 한 곳에만 있다.
- 다른 페이지 제안 문구의 마디 번호를 곡 번호로("2마디" → "18마디").

### v2.02 — 볼타 그리기·배포 zip
- **볼타 꺾쇠**: 번호 글자가 옛 엔진 기준 크기(ss×2.6×3 ≈ 7칸)로 남아 오선을 덮었다 → 숫자 높이 약 2칸(_font(ss×2.7)). 다리 2칸, 선 굵기 0.1칸, 가로선은 왼쪽 다리에서 시작(마디선 쪽으로 삐져나오지 않게). 높이는 오선 위 4칸(원본과 같게). 줄 첫 마디의 볼타는 음자리표·조표 뒤(첫 음 1.2칸 앞)에서 시작. 오른쪽 다리는 되돌이(:|)로 끝나는 볼타만(마지막 볼타·줄을 넘는 볼타는 열린 끝).

### v3.40 — 붓: 셋잇단음표·박자표, C 박자표 그리기, Esc로 붓 끄기
- 실사용(설치판 데모 악보): 11마디 윗보표 셋잇단 괄호를 칠해도 후보에 없음, 9마디(둘째 줄) C 박자표도 없음, Esc 뒤에도 붓이 켜져 있음.
- **원인 — 셋잇단**: Audiveris가 아랫보표 셋잇단만 읽고 윗보표는 놓침(A G F E D를 성부 1~4로 쪼갬 → 마디 '부족'). 붓 후보에는 잇단음표 자체가 없었다.

- 실측(데모): 셋잇단 괄호 → 1순위 셋잇단(0.95), 11마디 '부족' → 정상. C → 1순위 박자표 C(0.97), 3/4 → 1순위 3/4.

### v3.20 — 조카 피드백: 조바꿈 오류·그림 악보 코드 인식·끌어다 놓기
- **조바꿈 ①임시표(`editing._respell_accidentals`)**: 예전엔 옮긴 음마다 조표하고만 견줘 임시표를 붙였다 — 같은 마디에서 앞 음의 임시표가 뒤 음에 이어지는 규칙을 무시해 '♮ 뒤 다시 ♯'이 빠지는 등 표기와 실제 음이 어긋났다(화면·MusicXML은 임시표 값을 그대로 쓴다). 이제 마디마다 박 순서대로 보표·음이름·옥타브별 '지금 적용되는 변화'(처음엔 조표)를 따라가며 다를 때만 붙인다. 마디를 넘는 붙임줄 뒷음은 다시 적지 않는다. 검증(마디 안 임시표 규칙으로 계산한 음 ≠ 실제 음의 개수): 교회 E→C장조 51→70이던 것이 모든 목표 조(6가지)에서 **0**, 기도의 능력도 0.

### v2.60 — 붓으로 기호 넣기(새 기능)
- **원본 이미지 왼쪽 위의 붓 버튼(🖌, 늘 떠 있음) 또는 B로 켜고 끈다.** 켜면 원본 위를 끌어 분홍 반투명으로 칠한다(Ctrl+휠 = 붓 크기, 오른쪽 끌기 = 화면 이동, Esc = 칠한 것 지우기). 손을 떼면 칠한 영역의 원본 잉크를 읽어 **붓 버튼 옆에 후보를 가능성 순으로** 띄우고, 사용자가 원하는 후보를 누르면 편집 악보의 같은 자리에 넣는다(되돌리기 가능). 더블클릭(점 하나)으로는 '어디까지가 그 기호인지' 알 수 없던 작은 이음줄·쐐기를 위한 방법.
- **판단(`omr_bridge/brush.py`)**: 칠한 영역 ∩ 잉크에서 알고 있는 것(오선 줄 자리·머리·기둥)을 빼고 남은 잉크의 모양으로 — 점 모양(작고 둥근: 머리 오른쪽 같은 높이면 부점, 같은 세로줄 위·아래면 스타카토), 짧은 가로선(테누토), 긴 선 중 한쪽이 벌어진 두 선(쐐기 <·>: 벌어진 쪽으로), 열마다 한 덩어리인 휜 선(이음줄·붙임줄 — 곡선은 4차식 맞춤, 어긋난 조각 제외). 후보 키(내부 값): slur·tie·cresc·decresc·staccato·tenuto·dot — 화면 문구와 분리.
- **넣기**: 이음줄·붙임줄 = 곡선 양 끝에 가장 가까운 음(머리 또는 원본 기둥 끝을 붙는 자리로 — 기둥 쪽 이음줄), 시작 음은 그 줄의 모든 보표에서·끝 음은 같은 보표에서(기둥 아래 이음줄은 아래 보표 쪽에 가까울 수 있어 '가까운 보표'로 정하면 틀림), 원본 잉크 곡선 그대로(`src_poly`). 쐐기 = 원본 좌표(x1·x2·가운데 높이·벌어진 높이). 스타카토·테누토 = 같은 세로줄 음에 원본 자리(dx, dy). 점 = 바로 왼쪽 같은 높이 음(화음이면 전부).

  - 수정: 줄 첫머리 도돌이는 키 -1로 적고, 원본 자리(그 줄 보표들의 마디선 중 오선 왼쪽 끝 다음 것의 x — 굵은 선)를 키 -2로 → `Measure.start_repeat_x`. 그리기는 그 원본 x에 파트마다 굵은 선 + 얇은 선 + 점(원본이 정한다). MusicXML은 원래대로 forward repeat.

### v2.10 — 아티큘레이션·머리 가로 위치·덧줄 기준
- **아티큘레이션(악센트·스타카토·테누토·스타카티시모·마르카토)**: Audiveris가 인식해 화음과 짝지어 준 것(`chord-articulation` 관계)을 화음 대표 음의 `Element.articulations`([{kind, above, dx, dy}] — 머리 가운데 기준 원본 거리)로 붙여 원본 자리에 SMuFL 글리프로 그리고, MusicXML `<articulations>`로 내보낸다. 거름: 신뢰도 0.5 이상 · 머리에서 4.5칸 안(스타카토·테누토는 2.2칸 안 — 볼타 "1."의 마침표 제외) · 노래 파트 보표 아래(가사 자리) 제외("교회" 3쪽 합창 가사 '—'·글자를 TENUTO·ACCENT로 다수 오인) · v1.32에서 부점으로 바꾼 점 제외 · 테누토가 '오선 밖 머리와 오선 사이(또는 머리를 지나는)' 가로선이면 덧줄로 보고 제외. ※ 처음엔 '오선 줄 자리의 가로선 = 덧줄'로 걸렀으나, 크게 확대해 보니 오선 밖에서는 진짜 테누토도 줄 자리에 온다 — 그 규칙은 버렸다. 실측 "교회": 악센트 87·테누토 46·스타카토 2(모두 원본 확인).
- **머리 가로 위치(layout)**: Audiveris 경로의 `src_x`는 '머리 왼쪽 끝'인데(옛 엔진은 기둥 x) 그리기는 이를 머리 '가운데'로 써서 **모든 머리가 반 머리만큼 왼쪽**에 그려졌다(임시표가 머리에 붙고, 2도로 비킨 머리가 기둥에서 떨어져 보이던 원인). `src_x`가 머리 상자 왼쪽 끝과 같으면 상자 가운데를 쓴다(편집으로 옮긴 음은 그대로). 원본과 겹쳐 보면 머리·기둥·빔·악센트가 거의 정확히 포개진다.
- **임시표 자리**: 원본에 찍힌 x(머리 가운데 기준 거리, `Element.acc_dx`)에 그리고, 마디선과 최소 0.7칸 띄운다.
- **이음줄 방향**: 인식된 곡선이 실제로 휜 방향(SLUR_ABOVE/BELOW)을 `Arc.src_above`로 넘겨 그대로 그린다(모를 때만 기존 규칙).
- **덧줄 길이 기준**: 머리 폭 + 양쪽 0.3칸(SMuFL 기본 0.4칸, Gould『Behind Bars』 약 1/4 머리의 사이). 예전 ±1.9×머리 반폭(전체 약 2.5칸)은 원본보다 길었다. 검정 머리 기준 전체 약 1.8칸.
- **볼타 번호**: 높이 약 1.8칸(_font(ss×2.45)).
- 남은 한계: "Sub. p"의 'Sub.'처럼 셈여림 앞 글자는 스캔 악보에서 Audiveris 글자 인식 결과가 없어 읽지 못한다.

### 책 처리에서 함께 고친 인식 문제(한 페이지에도 적용)
- **조표 다수결(`mxl_reader._majority_keys`)**: 예전엔 첫 파트의 조표만 읽었다. "교회" 2쪽 셋째 줄은 맨 위 합창 보표의 조표만 못 읽어(다른 3보표는 ♯4개) 24마디부터 곡 전체가 다장조가 됐다. 마디마다 파트들의 조표 다수를 따른다(동률이면 앞 조표 유지). 음높이는 모델이 조표+임시표로 계산하므로 함께 바로잡힌다.
- **볼타(1·2절 꺾쇠)**: Audiveris가 인식한 `<ending>` inter(보표마다 하나씩 → 줄마다 하나로)를 model의 voltas로. 번호는 MusicXML의 `<ending number>` 차례. Audiveris는 작은 숫자를 자주 틀려(40마디 '2.'를 1로) `renumber_endings`가 음악 규칙으로 고친다(앞 볼타 뒤 되돌이가 있었고 번호가 앞 번호 이하면 +1).

## 10. 여러 페이지 설계 (v2.00) — 합의된 방향

### 보기 방식: **페이지 넘김**
선생님 의견에 따라 이어 붙이기 대신 페이지 넘김으로 정했다.
- 편집할 때 현재 페이지만 다시 그려 반응이 빠르다.
- 메모리가 한 페이지 분량으로 일정하다.
- 첫 페이지를 빨리 보여 줄 수 있다.
- 재생 중 페이지가 따라 넘어간다.
- 원본 PDF와 대응한다.

### 데이터 구조
- **곡 전체를 하나의 Score로** 둔다(재생·마디 검사·내보내기는 곡 전체 기준).
- 각 마디에 페이지 번호를 두고, 화면만 페이지 단위로 그린다.
- 뒤 페이지를 읽는 동안 앞 페이지를 편집해도, 새 페이지 내용은 뒤에 덧붙기만 한다.

### 점진 로딩 — 실측으로 확인
Audiveris는 PDF를 문서(book)째 받아 페이지를 이어서 처리할 수 있다.
```
# 1단계: 1페이지만 처리하고 저장
Audiveris -batch -sheets 1 -save -export -output OUT -- book.pdf     # 이 환경 39초
# 2단계: 저장본(book.omr)에 2페이지를 이어서 처리
Audiveris -batch -sheets 2 -save -export -output OUT -- OUT/book.omr  # 39초, "Time value reused from sheet#1"
```
- .omr에는 `sheet#1/sheet#1.xml`, `sheet#2/sheet#2.xml`이 쌓인다.
- 문서째 처리하면 마디 번호가 페이지를 넘어 이어지고, 파트 구성도 유지된다. 피아노만 있는 줄에는 빈 노래 파트를 채운다.
- Audiveris는 PDF를 **300dpi**로 읽는다(2480×3508). 지금 우리 경로(400dpi)와의 정확도 차이를 시험하고, 필요하면 해상도 상수를 넘긴다.
- geometry 파서를 시트별로 확장하고, 마디 id 오프셋을 계산하며, 글자 추출을 페이지별로 돌려야 한다.

### 화면·재생·내보내기
- **화면:** 상단에 ◀ 2/5 ▶ + 페이지별 상태(인식 완료/인식 중). 원본 패널도 같은 페이지. 페이지 경계의 붙임줄·쐐기는 반쪽으로(줄 끝 처리와 같은 방식).
- **재생:** 곡 전체를 재생하며 현재 음이 있는 페이지로 자동 전환.
- **내보내기:** 곡 전체를 한 번에. 아직 인식 중인 페이지가 있으면 "n페이지까지만" 안내.
- **캐시:** 문서 단위로 저장하고, 몇 페이지까지 처리했는지 기록한다.

## 11. 화면 구조 재설계 (v3.00) — 제안된 방향

- **기능 목록(액션 레지스트리):** 모든 편집 기능을 `내부 키 · 표시 문구 · 단축키 · 아이콘 · 사용 가능 조건`으로 한 곳에 등록하고, 버튼·메뉴·단축키·도움말을 여기서 자동 생성한다. 새 기능은 한 줄 추가로 끝난다.
- **오른쪽 편집 패널(접기 가능):** 분류별 탭을 두고, 선택 대상에 따라 쓸 수 있는 것만 켠다.
  - 음표(길이·점·쉼표·꾸밈음)
  - 음높이·임시표
  - 성부·화음
  - 기호(이음·잇단·셈여림·쐐기·늘임표)
  - 마디(박자·조표·음자리표·반복)
  - 글자(가사·곡 정보)
- **하단 막대 축소:** 선택 정보 + 자주 쓰는 몇 개만.
- **기능 찾기:** Ctrl+K로 이름 검색해 실행, F1로 단축키 전체 목록(레지스트리에서 생성).
- **페이지 넘김 막대(v2.00)와 통합.** 1366 폭 화면에서도 잘리지 않게.

## 13. 작업 방식 (지금까지의 약속)

- 설명은 한국어로 한다. 문제는 **원인을 먼저 진단해 근거(수치·비교 이미지)와 함께** 설명하고 고친다. 확인만 요청받으면 고치지 않는다.
- 수정 후에는 실제 악보로 원본과 나란히 비교하고, 다른 시험 악보의 결과가 바뀌지 않았는지 확인한다.
- 결과물은 `OMR_Sprouty_vX.XX.zip`으로 묶어 전달하고, 버전은 2절 규칙을 따른다.
- 내부 키와 화면 문구를 분리한다.
- 큰 변경은 설계를 먼저 제안하고 합의한 뒤 진행한다.
